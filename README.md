# Codex Account Switcher

在 VS Code 中儲存、管理及切換多個 ChatGPT 帳號，並在狀態列查看各帳號的 Codex 額度。聊天、模型、工具與歷史對話沿用 OpenAI 官方 Codex 擴充套件。

目前版本：**0.3.4 · Windows x64**。

免重載切換仍是實驗性功能，需要先啟用。它切換的是**目前 VS Code 視窗的 Codex 後端**；由其他視窗或桌面版持有的舊對話，可能仍使用該客戶端的帳號。本工具不提供每個視窗各自隔離帳號的功能。

## 開始使用

### 安裝與首次啟用

1. 使用本機 Windows x64、VS Code 1.100 以上版本，並信任目前工作區。
2. 安裝 OpenAI 官方 **Codex** 擴充套件（`openai.chatgpt`），完成 ChatGPT 登入。
3. 執行 **Extensions: Install from VSIX…**，選擇 `multi-codex-win32-x64-0.3.4.vsix`，依 VS Code 提示套用新版。
4. 點擊狀態列 **Codex: 帳號 → 啟用免重載切換**。
5. 完成進行中的工作後，按提示的 **重新啟動擴充**。

首次啟用需要重啟擴充執行環境，其他擴充也會一起重啟。啟用完成後，一般帳號切換不會重新載入視窗；執行中的任務或請求會阻擋切換。

### 保存及新增帳號

1. 點擊 **Codex: 帳號 → 儲存目前帳號**，保存現有登入。
2. 選擇 **新增帳號**，在開啟的官方登入網頁選擇另一個 ChatGPT 帳號。
3. 完成登入後核對 email，按 **套用**。套用會保存新帳號並切換過去。

新增帳號在獨立暫存目錄進行官方登入，原帳號會先保存，不需登出。取消登入或取消套用，均不替換目前帳號。請使用此流程新增帳號；登出官方 Codex 可能撤銷先前保存的憑證。

### 日常切換與管理

先完成目前的 Codex 任務，再點擊狀態列、選擇已儲存帳號。後端確認帳號切換成功後，才更新原生登入檔。其他正在使用同一登入目錄的 Codex 視窗／CLI 應先完成工作並關閉，以免共用登入狀態互相影響。

主選單最多列出 **100 個已儲存帳號**，可捲動及搜尋。每個帳號右側提供三個按鈕：

| 按鈕 | 用途 |
| --- | --- |
| 修復（循環箭頭） | 重新登入同一帳號與工作區，更新失效憑證，保留帳號名稱。 |
| 改名（鉛筆） | 修改清單中的顯示名稱。 |
| 移除（垃圾桶） | 確認後移除已儲存的登入備份，不會登出官方 Codex。 |

不再提供獨立的「管理已儲存帳號」子選單。命令面板搜尋 **Codex Accounts:**，也可使用切換、新增、儲存、修復、開啟官方 Codex，以及啟用／停用免重載功能。

## 查看額度

狀態列分別顯示各帳號的**已使用比例**，例如：

```text
● A：5h 20%／Week 40%    B：5h 65%／Week 80%
```

以上為示意數字。0% 表示該週期尚未使用，100% 表示已用完；只顯示伺服器實際提供的週期。`A`、`B` 依儲存清單順序編號，移除帳號後可能重新排列。`●` 表示目前**登入檔中的帳號**，不保證其他客戶端持有的舊對話也使用同一帳號。

滑鼠移到額度上，可查看名稱、email、重置時間與最後成功更新時間；點擊即可開啟帳號清單。尚未儲存的目前登入帳號也會顯示。

### 自動更新頻率

| 情況 | 預設行為 |
| --- | --- |
| 啟動或成功切換帳號後 | 等待 5 秒開始檢查；有新鮮共用快取時直接沿用。 |
| VS Code 在前景 | 每個帳號約 1 分鐘查詢一次。 |
| 所有共用視窗都在背景 | 每個帳號約 3 分鐘查詢一次。 |
| 查詢失敗 | 保留上次成功結果，連續失敗時逐步延長重試間隔。 |

正常使用無需手動刷新，主選單與命令面板已移除刷新入口。查詢失敗時，舊數值會標示「（上次）」；從未成功取得資料時顯示「無法取得」。滑鼠提示會說明錯誤與最後成功時間。

**兩個視窗不會因此變成每 30 秒查詢一次。** 同一 VS Code Profile／共用資料目錄中的 0.3.3 以上視窗，會共用每個帳號的查詢時間與查詢鎖。某視窗剛查過，另一個會沿用結果；同時到期時也只由取得鎖的視窗查詢。此去重機制以共用快取正常讀寫為前提，不同 Profile 或獨立資料目錄不共用。兩個帳號每輪各有一次請求，屬於不同帳號的查詢。

### 設定

在 VS Code 設定搜尋 `multiCodex.quota`：

| 設定 | 預設值 | 說明 |
| --- | --- | --- |
| `multiCodex.quota.enabled` | `true` | 自動查詢額度。關閉不影響帳號切換。 |
| `multiCodex.quota.refreshIntervalMinutes` | `1` | 前景查詢間隔，範圍 1–1440 分鐘。 |
| `multiCodex.quota.backgroundRefreshIntervalMinutes` | `3` | 背景查詢間隔，範圍 1–1440 分鐘。 |

查詢失敗的重試間隔逐次加倍，通常最長 6 小時；自訂間隔大於 6 小時時，以該間隔為下限。失敗後若憑證更新，會在下一次自動檢查重新嘗試。

## 常見問題

### 顯示已換帳號，舊對話卻仍報額度用完

官方介面可能正在跟隨另一個客戶端持有的對話，訊息會交給該客戶端送出。這時本視窗的登入顯示與舊對話實際使用的帳號可能不同，重載或重開本視窗也不會替另一個客戶端換帳號。

先在目前 VS Code **新建對話**核對切換結果。若要繼續舊對話，完成工作後關閉持有該對話的其他 Codex 客戶端，再重新開啟對話並確認。跨帳號接續特定雲端對話不保證可用；本工具不會自動搬移任務或關閉其他客戶端。

### 顯示「尚有任務或請求進行中」

等待工作完成後再切換。這項保護避免執行中的工作改用另一個帳號，不會強制中止任務。

### 顯示共用登入身分不同，或橋接仍使用舊後端

先完成工作並關閉其他共用登入資料的 Codex，再按錯誤提示的 **重新啟動擴充**，完成同步後重選帳號。官方擴充更新後，也可能需要這一步套用新的後端路徑。

### 出現 `refresh token was revoked`、憑證過期或無法刷新

使用該帳號旁的**修復**按鈕，在瀏覽器登入原本的帳號與工作區，再按 **套用**。被撤銷的憑證無法只靠切換或重載恢復。額度查詢本身不刷新憑證，備用帳號過期時也需要修復。

### 自動查詢會不會再次觸發先前的 LSASS 問題

額度查詢直接使用 HTTPS，不會啟動 Codex／curl、刷新憑證、寫入登入檔或建立暫存登入目錄，因此已移除「每次查額度都反覆啟停 Codex」的路徑。

先前 LSASS 異常的真正根因尚未證實，不能宣稱 Windows 問題已修復或保證不再發生。新增／修復帳號及切換時必要的憑證更新，仍會使用官方 Codex 程序。

### 如何停用免重載切換

從帳號選單選擇 **停用免重載切換**，或執行 **Codex Accounts: Disable Seamless Switching**，再依提示重新啟動擴充。已儲存帳號會保留。若要降版到尚無此功能的 0.2.6，請先完成停用。

## 更新與支援範圍

安裝新版 VSIX 不代表已開啟的擴充執行環境已載入新版。請先完成工作，再依 VS Code 提示套用；橋接若另提示更新，也需按 **重新啟動擴充**。本工具不會自動重啟進行中的工作。

免重載功能透過 `chatgpt.cliExecutable` 啟動本機橋接，再啟動官方原版後端，不修改官方擴充套件檔案。若已有其他自訂 CLI，啟用會停止並提示，不會覆寫。登入使用實驗性的 `chatgptAuthTokens` 協定，官方更新後需要重新確認相容性，因此目前仍保留啟用／停用入口。

目前僅支援本機 Windows x64、已信任工作區、ChatGPT 帳號與 `file` 登入儲存。WSL、遠端視窗、虛擬工作區、API Key 登入、`keyring`／`auto` 儲存，以及固定 ChatGPT 工作區設定不在支援範圍。進階使用者若需調整儲存方式，可在 Codex `config.toml` 設定 `cli_auth_credentials_store = "file"`，重新載入並登入後再儲存；本工具不會自動改寫該設定。

## 登入資料與診斷

- 已儲存帳號的憑證放在 **VS Code SecretStorage**，不寫入一般設定、工作區、紀錄或套件。
- 官方登入檔使用 VS Code 程序的 `CODEX_HOME`；未設定時使用 `%USERPROFILE%\.codex`。切換會更新其中的原生 `auth.json`，其他共用此目錄的 Codex 可能受影響。
- 切換會保存目前最新憑證，必要時透過隔離的官方 CLI 更新；橋接只接收 access token。登入檔若被其他程序更動，不會直接覆寫；切換失敗會嘗試還原後端，無法確認還原時明確報錯。
- 額度查詢只傳送該帳號的 access token 與工作區 ID，總逾時 10 秒、不跟隨轉址。使用的是未公開後端介面，可能因服務改版或網路限制而失敗。
- VS Code **輸出 → Codex Accounts** 可查看登入輔助程序的用途、PID、結束代碼及是否強制終止；紀錄不包含憑證。

## 開發與驗證

在 Windows x64、Node.js 20.19 以上環境執行：

```text
npm ci
npm run typecheck
npm run build
npm test
npm run test:integration
npm run package
```

建置需要 Windows 內建的 .NET Framework C# 編譯器。`src/switcher/` 負責帳號、額度與 VS Code 介面，`src/bridge/` 負責啟動器與後端橋接。

`npm test` 使用合成登入資料，涵蓋切換、失敗還原、列按鈕、100 帳號上限、額度排程與多視窗去重。`test:integration` 使用隔離 VS Code 的真實 SecretStorage；可用 `MULTICODEX_TEST_CODE` 指定測試用 Code.exe。

設定 `MULTICODEX_OFFICIAL_EXTENSION` 為已安裝的官方擴充目錄後，另有 `npm run test:official-ui` 驗證隔離的未登入官方介面啟動，以及 `npm run test:auth-routing` 驗證真實官方後端搭配合成帳號與本機 API 的路由。後者不呼叫付費模型。

`scripts/live-bridge-probe.ts` 與 `scripts/quota-probe.ts` 另提供明確使用目前真實帳號的唯讀診斷，需帶 `--current-access-token`；操作範圍見下列驗證紀錄。舊 `test:reload` 供歷史流程回歸，不作為免重載驗收證據。

0.3.4 的既有驗證包含 102 項測試、隔離 Extension Host、官方介面啟動及本機模擬 API 的帳號路由。**兩個真實帳號的完整官方 UI 切換、自然憑證到期續用及跨客戶端接手仍待驗收**，不能只以這些自動測試宣稱完全通過。

詳細驗證範圍與重現方式見[驗證摘要](docs/public/validation.md)。
